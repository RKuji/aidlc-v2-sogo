# Requirements — 単位数表マスタ(CSV)の取り込み・表示

Sources: `../../ideation/intent-capture/intent-statement.md`, `../../ideation/scope-definition/scope-document.md`, `../practices-discovery/team-practices.md`, `requirements-analysis-questions.md` (Q1-Q8).

## Intent Analysis

介護予防・日常生活支援総合事業費の単位数表マスタをCSVから正確に取り込み・検証・保存し、介護サービス事業者・ケアマネジャー等が保険者番号・サービス種類コードで絞り込んで正しい単位数データを参照できるようにすることが目標である(`intent-statement.md`)。単なるデータ投入ではなく、21列(全22列中、予備項目を除く)の検証ルールを漏れなく適用し、後続の請求・サービス計画業務が誤ったデータを参照するリスクを排除することが本質的な狙いである。

## Functional Requirements

### FR-A: CSV取り込み

- **FR-A1**: システムはローカルに保存されたCSVファイルを1つ選択してアップロードできなければならない。一度のアップロードで受け付けるファイルは1つのみとし、複数ファイルの一括アップロードは対象外とする(Q4)。
- **FR-A2**: アップロードするCSVファイルの文字エンコーディングはShift-JISを前提とする(Q1)。
- **FR-A3**: ファイルサイズの上限は設けない(Q4)。
- **FR-A4**: アップロードされたCSVは、FR-Bで定義される21列すべての検証ルールに従って検証される。
- **FR-A5**: アップロードされたファイルが以下のいずれかに該当する場合、列単位の値検証(FR-B2)を行う前に構造エラーとして取り込みを拒否し、エラー内容(具体的にどの構造要件を満たさないか)を画面に表示する: (a) 列数が22列と一致しない、(b) ファイルが空である(0バイト、またはヘッダー行のみでデータ行が0件の場合を含む)、(c) Shift-JISとしてデコードできない(FR-A2の前提に反する)。本チェックはファイル構造の前提条件を扱うものであり、FR-B1のcollect-all方針(列単位の値検証における全違反収集)の対象外である。
- **FR-A6**: 取り込みに成功した場合、ユーザーには取り込み成功のメッセージと、取り込まれた行数(ヘッダー行を除くデータ行数)を画面に表示する。

### FR-B: CSV検証(collect-all方式)

- **FR-B1**: 検証はcollect-all方式とする。1行・1ファイルにつき最初に検出した違反で処理を中断せず、21列すべてのルールを全行に対して適用し、違反の完全なリストを1回のパスで返さなければならない(`team-practices.md` Testing Posture, project.md Mandated)。
- **FR-B2**: 検証対象は全22列のうち、予備項目を除く21列である(予備項目はCSV定義表で定義欄が空のため検証対象外, `project.md` DECIDED):

  | # | 列名 | 検証ルール |
  |---|---|---|
  | 1 | 証記載保険者番号 | 6桁の数値であること |
  | 2 | ｻｰﾋﾞｽ種類ｺｰﾄﾞ | 2桁の数値であること |
  | 3 | ｻｰﾋﾞｽ項目ｺｰﾄﾞ | 4桁の数値であること。有効なコード値の一覧(外部の指定コードマスタ)は本ステージの入力に含まれておらず、桁数・数値形式のみを検証する。値の妥当性(存在するサービス項目コードか)まで検証するかは未確定 — 下記Open Questions参照 |
  | 4 | 適用開始年月日 | 6桁YYMMDD形式(西暦下2桁+月2桁+日2桁)であること。元の仕様書表記「YYYMMDD」は7文字で「6桁」と矛盾していたため、ユーザー確認によりYYMMDD(6桁)を正としている(訂正 2026-08-10) |
  | 5 | 適用終了年月日 | 6桁YYMMDD形式(西暦下2桁+月2桁+日2桁)であること。適用開始年月日と同じ形式の訂正を適用(訂正 2026-08-10) |
  | 6 | ｻｰﾋﾞｽ名称 | 任意の文字列(形式制約なし) |
  | 7 | 単位数 | -9999〜99999の範囲の数値であること |
  | 8 | 算定単位 | 01・02・03・05のいずれかのコードであること |
  | 9 | 制限日数・回数 | 0〜99の範囲の数値であること |
  | 10 | 算定回数制限期間 | 01・08・16・00のいずれかのコードであること |
  | 11 | 支給限度額対象区分 | 3または0のいずれかであること |
  | 12 | 予備項目 | 検証対象外(定義なし) |
  | 13 | 給付率 | 1〜100の範囲の数値であること |
  | 14 | 利用者負担額 | 5桁までの数値であること |
  | 15 | 事業対象者実施区分 | 1または2のいずれかであること |
  | 16 | 要支援1受給者実施区分 | 1または2のいずれかであること |
  | 17 | 要支援2受給者実施区分 | 1または2のいずれかであること |
  | 18 | 要介護1受給者実施区分 | 1または2のいずれかであること |
  | 19 | 要介護2受給者実施区分 | 1または2のいずれかであること |
  | 20 | 要介護3受給者実施区分 | 1または2のいずれかであること |
  | 21 | 要介護4受給者実施区分 | 1または2のいずれかであること |
  | 22 | 要介護5受給者実施区分 | 1または2のいずれかであること |

- **FR-B3**: 1件でも検証違反が検出されたCSVファイルは、取り込み(DBへの保存)を行わない(`intent-statement.md` [desc])。
- **FR-B4**: 検証に失敗した場合、ユーザーには画面上でcollect-all方式によって収集された全違反のリストを表示する。ダウンロード可能な形式でのエクスポートは今回のスコープでは提供しない(Q3)。
- **FR-B5**: FR-B4で表示する各違反は、少なくとも「行番号(ヘッダーを1行目とするCSVファイル上の物理行番号)」「列名」「違反したルール(またはエラーメッセージ)」「実際の値」の4項目を含まなければならない。

### FR-C: データ保存

- **FR-C1**: 検証に合格したCSVの全行をDBに保存する。
- **FR-C2**: 既存レコードと同一の保険者番号+サービス種類コード+サービス項目コード+適用開始年月日の組み合わせを持つ行を再取り込みした場合、最新の取り込み内容で既存レコードを上書きする(履歴は保持しない)(Q2)。

### FR-D: 検索・表示

- **FR-D1**: ユーザーは取り込み済みデータの中から保険者番号を選択できなければならない。
- **FR-D2**: ユーザーは取り込み済みデータの中からサービス種類コードを選択できなければならない。
- **FR-D3**: 選択した保険者番号・サービス種類コードの組み合わせに一致する登録済みデータを表形式で表示する。
- **FR-D4**: 表示テーブルには主要な列(保険者番号、サービス種類コード、サービス項目コード、サービス名称、単位数、適用期間)を表示し、それ以外の詳細列は行クリックによる展開表示とする(Q5)。

### FR-E: 列名マッピング

- **FR-E1**: CSVの日本語/半角カタカナ列名(証記載保険者番号、ｻｰﾋﾞｽ種類ｺｰﾄﾞ等)と、コード内で使用する英語camelCase識別子との対応表を、リポジトリ内の文書(スキーマ定義に付随するドキュメントまたはコード内コメント)として作成し、TypeScriptの型・Zodスキーマ・Prismaモデルの3層すべてがこの対応表を参照しなければならない。対応表が存在しない、またはいずれかの層がそこから乖離している場合はこの要件を満たさない(`team-practices.md` Code Style, project.md Mandated)。

## Non-Functional Requirements

- **NFR-1(テスト)**: 確認済みの6つのテストツール(Vitest、Testcontainers、Storybook、MSW、Playwright、MagicPod)すべてを`main`へのマージ前にブロッキングなCIチェックとして実行する(`team-practices.md` Testing Posture)。最低80%のライン カバレッジを下限とする(org.md デフォルト)。
- **NFR-2(性能)**: 特定の性能目標(応答時間・データ量上限)は設けない。内部業務システムとして妥当な応答性能であればよい(Q6)。
- **NFR-3(アクセシビリティ)**: 特別なアクセシビリティ要件はなく、Radix UI(アクセシビリティ対応済みのheadless UI)のデフォルト挙動に従う(Q7)。
- **NFR-4(セキュリティ)**: CIにdependency scanningとsecret scanningを組み込み、マージをゲートする。SAST/DASTは本プロジェクトのスコープでは対象外とする(`team-practices.md` Code Style, project.md Mandated/Forbidden)。
- **NFR-5(デプロイ)**: マージ時にstaging環境へ自動デプロイし、production環境へは別途の手動承認(テックリード+プロダクトオーナー承認)を経てデプロイする(`team-practices.md` Deployment)。
- **NFR-6(アーキテクチャ)**: Hono(API層)→サービス層→Prisma(データ層)の3層構造を遵守する(`team-practices.md` Code Style)。

## Constraints

- 技術スタックはNext.js/React/TypeScript、Radix UI、Tailwind CSS、SWR/Zustand/nuqs、React Hook Form/Zod、Hono/OpenAPI/openapi-fetch、Aurora PostgreSQL/Prismaに固定されている(`intent-statement.md`)。
- CSVの列名は日本語/半角カタカナのソース表記であり、コード内(TypeScript/Zod/Prisma)では英語のcamelCase識別子にマッピングする(具体的な検証可能要件はFR-E1を参照)。
- ワークフロースコープ`csv-master-import-display`により、market-research・feasibility・team-formation・rough-mockups・user-stories・units-generation・delivery-planning・functional-design・nfr-requirements・nfr-design・infrastructure-design・運用系ステージはすべてSKIPされている(`scope-document.md`)。

## Assumptions

- CSVファイルの取り込み操作は、エンドユーザー(サービス事業者・ケアマネジャー等)自身が行う(`intent-statement.md`, intent-capture Q9)。

## Out of Scope

- 複数ファイルの一括アップロード(Q4)
- 重複レコードのバージョン管理・履歴保持(Q2で上書き方式を採用したため対象外)
- 検証エラーレポートのダウンロード/エクスポート機能(Q3)
- ページング・並び替え等の付加的なUX改善(`scope-document.md`)
- 他システム(既存保険者マスタ等)との連携(`scope-document.md`)
- SAST/DASTを含む本格的なセキュリティパイプライン(`team-practices.md`)
- 証記載保険者番号マスタテーブルの追加(将来的な拡張候補として`scope-document.md`に記録済み、今回のスコープでは対象外)

## Open Questions

- FR-B2 row 3(ｻｰﾋﾞｽ項目ｺｰﾄﾞ)は桁数・数値形式のみを検証する。値が実在する指定コード(外部の指定コードマスタに存在する値)かどうかまで検証するかは未確定。指定コードマスタが本プロジェクトのスコープ内で参照可能か、次のapplication-designステージで確認が必要。
